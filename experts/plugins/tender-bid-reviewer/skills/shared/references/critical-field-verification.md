# 关键字段可信度核验

在拟对姓名、签署、印章遮挡文字、证书/证件号、金额、日期、账号、型号作一致性、高风险或资格判断时使用。本规程不适用于普通条款摘要，也不要求为每个字段开启字符级解析。

## 1. 先定义比较对象

先写清字段所属角色与来源，例如：法定代表人、被授权人、签署人、人员证书持有人、收款账户主体。角色不同、授权关系不同或同名不同人，都不能只凭姓名字符串判定冲突。

仅比较“本应一致”的字段：同一角色在同一份或应配套的文件中的姓名、同一证件号、同一报价口径的金额等。

## 2. 何时升级核验

若 Markdown 初读的关键字段出现不同读法，且有任一情形，必须先核验再分级：

- 字段来自手写、扫描图、图片元素，或被公章、签名线、骑缝章等遮挡；
- 字符详情缺失，任一关键字符置信度低于 `0.90`，或存在有意义的候选字竞争；
- OCR 漏字、断字、换行拼接、页码映射或表格单元格归属存在疑问；
- 该差异将导致“人员不一致、签署不合格、资质不符、报价冲突”等高风险结论。

## 3. 定向核验流程

1. **复用现有结果**：先从会话台账取得 `doc_id`、元素 ID、PDF 物理页码和已有 JSON；不要重跑全文。
2. **取得字符详情**：仅对疑似页或元素使用 `xparse-cli --profile workbuddy get_confidence <doc_id> --element-id <id>`，或使用 `--page <n>`；若当前没有可用缓存/JSON，才对该页补一次 `--view json --include-char-details` 解析。
3. **定位并进行多模态页面复核**：读取 JSON 中相应页面的 `page_image_url`，用 xParse `download` 下载该页图片后，交由当前 WorkBuddy 可用的图像查看/多模态能力复核；也可查看用户提供的原始 PDF 页面。若字符详情提供了 `bbox`，优先截取“字段周边小区域 + 足以识别表单角色的少量上下文”供复核，同时保留原页以核对位置。只下载和查看疑似页，不重新生成整份文件的页面图。
4. **解释多模态复核结果**：多模态模型只对页面中实际可辨的笔画、印刷字和字段位置作判断，不得基于姓名常见性、上下文臆测或候选字补全被印章完全遮住的内容。视觉结论需与 OCR 初读、字符置信度/候选和同角色可读证据一起记录；当前会话不具备图像查看能力、图片下载失败或页面仍不可辨时，明确记为“未完成视觉复核”，停止猜测。
5. **交叉验证**：与同角色的可读原件、身份证明/授权关系、营业执照、证书或同一表单的可确认字段比对。不得把法定代表人自动当作被授权人，也不得仅因“更常见”而改写字段。
6. **形成结论**：
   - 原始页面确认两处可比字段不同：可报告明确差异；
   - 页面显示 OCR 误读：保留“OCR 初读”说明，并以页面复核值作为审阅结论；
   - 页面无法辨认或证据不足：标记 `🟡 OCR 待人工核验`，不写成已证实冲突。

不要根据候选字或多模态模型的推测自动改字；候选字只用于触发复核和解释不确定性。只有页面视觉可辨且有相应的同角色证据时，才可将其作为“页面复核值”。

## 4. 输出与定位

对触发核验的条目使用：

| 字段/角色 | OCR 初读 | 置信度/候选 | 多模态页面复核 | 可比对证据 | 结论/动作 |
|---|---|---|---|---|---|
| {签署人} | {原始 Markdown 读法} | {关键字符置信度与候选，或“无字符详情”} | {页面可见读法 / 未完成视觉复核 / 不可辨认} | {同角色来源} | {确认一致 / 已证实差异 / OCR 待人工核验} |

页面定位写为 `【文件名｜PDF 物理第 n 页｜文档页脚第 m 页（如可见）｜章节/表格】`。PDF 物理页与印刷页不一致时同时保留两者；无法确认印刷页时不要猜。

### 例：姓名被公章遮挡

若授权书正文、身份证明显示“温永强”，签署栏 OCR 初读为“温水强”，且“水”字符置信度低、候选含“永”，再由页面图可见手写为“温永强”，结论应为“OCR 误读已复核，不构成姓名不一致”。若页面图也无法辨认，则为“OCR 待人工核验”，而非高风险。
