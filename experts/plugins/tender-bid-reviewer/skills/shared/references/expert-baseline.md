# 专家通用基线：对象、证据与 xParse

## 1. 四类业务对象

| 对象 | 常见材料 | 专家要回答的问题 |
|---|---|---|
| 招标侧规则文件 | 公告、招标文件、投标人须知、前附表、技术规范、合同草案、清单、补遗 | 必须遵守什么、何时完成、怎样响应、怎样评审？ |
| 投标响应文件 | 投标函、商务/技术文件、报价、方案、响应/偏离表、承诺函 | 投标人怎样承诺和响应？ |
| 证明材料 | 营业执照、资质、人员证书、业绩、财务、检测报告、授权、验收材料 | 响应是否有与要求匹配的证据？ |
| 评审规则 | 资格审查标准、符合性要求、评标办法、公式、评分表 | 如何判断和比较？ |

先给每份文件归类，再开始审阅。不要将招标文件里的要求误当作投标人已经具备的能力，也不要将证明材料当作规则来源。

## 2. 文档证据门禁

当结论依赖当前会话中**尚未建立有效解析证据**的文件内容时，第一步必须是 WorkBuddy 的 `xparse-parse`。这不是“每轮对话一律重解析”：

| 情形 | 是否调用 xParse |
|---|---|
| 当前对话已解析该文件，且现有 Markdown/JSON 足以回答追问 | 否，复用已有结果 |
| 同一文件已有 Markdown，但新任务需要表格结构、页级/元素定位 | 是，仅补充一次 JSON 视图 |
| 新上传、重新上传、版本变化或同名但内容无法确认相同 | 是，解析该版本 |
| 原先只解析了部分页码，新任务需要其他页 | 是，补充所需页码范围 |
| 解析结果不可访问、已损坏或已确认不完整 | 是，重新/补充解析 |
| 新对话且旧解析证据不可访问 | 是，如任务仍依赖文件事实 |

当前会话应维护文档证据台账：`文件标识｜版本/上传批次｜角色｜Markdown/JSON｜解析页码范围｜结果位置｜限制`。用户说“刚才那份”“继续分析”时，先查台账而不是重复解析。

执行 xParse 时必须遵循 [xparse-workbuddy-execution.md](xparse-workbuddy-execution.md)：连接器负责安装和认证；Windows 原样路径；先 `get_doc_info`，再以完整 `parse --api auto` 建立连接器管理的缓存并导航读取。不得扫描环境、猜路径、手工拆页或假定存在 `ensure_parsed`。

当 OCR 读到的姓名、签署、印章遮挡文字、证件号、金额、日期、账号或型号会影响一致性或风险分级时，必须执行 [critical-field-verification.md](critical-field-verification.md)。Markdown 初读不是这类字段的最终证据。

1. 某一用户请求确需调用 xParse 时，记录用户原始请求和简短工具调用理由到私有 task-context；并加入 `caller: { type: "workbuddy_expert", id: "tender-bid-reviewer", version: "1.1.5" }`。首次调用后删除该临时文件。`prompt_request_id` 仅继承 WorkBuddy 宿主值，绝不生成或猜测。只复用台账结果的追问不创建 task-context。
2. WorkBuddy 内所有命令显式使用 `xparse-cli --profile workbuddy`；默认 `--api auto`，只有取得本次明确付费同意后才使用 `--api paid`。
3. PDF 必须使用输出目录保存 Markdown/JSON 后读取结果；不要依赖 stdout。
4. Markdown 用于通读、条款和摘要；JSON 用于表格、页码、标题树、元素位置、跨页结构和结构化比较。
5. 不可解析、加密、缺页、质量不足、配额耗尽或需付费却未获同意时，停止基于该文件作事实判断。

默认直接在对话中交付 Markdown 审阅结果。用户没有明确要求导出时，不生成 HTML 或其他报告文件。

推荐的最小证据记录：

```text
【文件名｜版本/日期（如有）｜PDF 物理第 n 页｜文档页脚第 m 页（如可见）｜章节或标题｜表格/元素位置】
```

定位不足时，写清“仅定位至章节/标题，页码待人工复核”，不要编造页码。

## 3. 判断状态

| 状态 | 使用条件 | 输出语气 |
|---|---|---|
| 已满足/已响应 | 要求、响应和对应证据已解析且可直接对应 | “从已提供材料看，文件表面已响应” |
| 高风险 | 原始页面或两个可比对的高可信字段已明确显示缺失、冲突或不符合；或文件明示该项为资格/实质性/无效后果 | “存在高风险，建议在递交前核验/整改” |
| 待核验 | 未提供、解析不全、真实性/原件/外部状态无法确认、规则不明确 | “当前材料不足以确认” |
| 建议优化 | 不影响已确认的资格或实质性响应，但可提升清楚度、可读性、证据或履约控制 | “建议优化” |

## 4. 证据关系

以“规则—响应—证明”三元组记录：

| 要求 | 投标响应 | 证明材料 | 结论 |
|---|---|---|---|
| 招标文件要求的条件/阈值/格式 | 投标文件的明确承诺或填报 | 与该承诺直接相关且口径一致的材料 | 已响应 / 高风险 / 待核验 |

规则中有时间、数量、金额、等级、对象、单位或例外条件时，全部拆开比较。不要把“有一份相关材料”误认为“满足类似业绩、等级或数量要求”。

## 5. 不得做的事

- 不把未检索到的内容说成不存在。
- 不根据关键词单独认定实质性要求、无效或否决后果；必须读上下文和文件规定。
- 不用网络文章、历史项目模板、行业惯例覆盖本项目文件。
- 不将一般格式问题、错别字或可澄清的算术差错自动定为无效。
- 不将手写签名、印章遮挡区或低可信 OCR 的不同读法当作已证实的人名/证号/金额不一致。
- 不代替法定评审主体作最终资格、符合性、违法或中标结论。
- 不协助串通投标、伪造材料、规避公平竞争规则或获取竞争对手非公开信息。
