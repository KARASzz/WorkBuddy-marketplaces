# 招标文件解读规则

## 1. 项目总览与日程

提取时不得遗漏或推测：项目名称/编号、标段、招标/采购人和代理机构、项目地点、范围、交付/工期/服务期、预算/最高限价（若明示）、文件获取、踏勘/答疑、澄清截止、保证金、投标截止、开标、投标有效期和签约/履约节点。

每一个时间节点写明：`事项｜日期/时间｜时区或地点（如明示）｜文件来源｜行动`。若公告与前附表/补遗冲突，列为待澄清或按文件明示的优先规则处理。

## 2. 资格条件结构化

对每项资格要求拆分：

| 字段 | 示例（仅为结构示例） |
|---|---|
| 条件对象 | 投标人 / 项目负责人 / 联合体成员 |
| 条件 | 具备某资质、业绩或信用条件 |
| 量化边界 | 近 N 年、至少 N 项、单项金额不少于 X |
| 口径 | 项目类型、合同范围、证书等级、注册单位 |
| 证明 | 合同、验收材料、证书、审计报告、社保等 |
| 例外/联合体 | 是否允许、谁须满足、可否累计 |
| 文件后果 | 文件明示的资格/无效/评分后果 |

不能用“资质齐全”“业绩足够”这种笼统词替代结构化条件。

## 3. 实质性要求与潜在否决风险

识别线索包括“实质性”“不允许偏离”“无效”“否决”“必须”“不得”等，但最终判断要看：

1. 条款是否明确将该要求列为资格、实质性或无效后果；
2. 条款的适用对象、阶段和例外；
3. 同一文件或补遗是否修正、澄清或限制该条款；
4. 当前制度是否允许澄清/算术修正，且不改变实质内容。

输出时区分：文件明示后果、专家提示的履约/评分风险、需要规则确认的程序风险。

## 4. 评分模型

| 类型 | 审阅方式 |
|---|---|
| 资格项 | 仅判断是否为前置条件，不得计入得分 |
| 符合性/实质性项 | 列响应要求和后果，不得当作加分项 |
| 客观评分项 | 提取条件、单位分、上限、证明、计数/取整规则 |
| 主观评分项 | 提取评价维度、分档和材料要求；不杜撰评委偏好 |
| 价格项 | 原样提取有效报价定义、公式、基准价、调整/修正、舍入和封顶规则 |

## 5. 技术、商务、报价与合同

- 技术：供货/服务范围、系统边界、参数、标准、接口、安装、测试、验收、培训、售后、质保、备件与安全要求。
- 商务/合同：价款类型、支付条件、保证金、交付、验收、变更、索赔、违约、责任限制、保险、分包、保密、知识产权和争议解决。
- 报价/清单：报价范围、税费、暂估/暂列、不可竞争费用、计量规则、工程量/服务边界、允许修正及价格评分方法。

对“项目范围是否包含某项工作”必须给出条款证据；不能仅因清单未列就认定不包含，还需交叉核对范围、规范、图纸、合同和澄清。
