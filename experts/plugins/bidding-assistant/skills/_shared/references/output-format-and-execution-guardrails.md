# 输出格式与执行护栏

本文件为 5 个招投标子技能的通用数据与执行规则。DOCX 的创建、格式和文档结构由 `word-document-processing` 自行处理，本文件不规定 Word 实现方式或排版参数。

## 1. 多格式数据一致性

- 同时生成 Word/HTML/JSON 时必须使用同一份规范化 JSON 作为唯一数据源，禁止分别推断或二次改写核心结论。
- 交付前逐项核对项目名称、评标办法、投标人、资格状态、评分/排序、★条款、风险等级、资质和推荐结论。
- 任一核心字段不一致时停止交付，优先修复数据映射或模板路由；不得手工只改其中一个格式。

## 2. 依据与来源标签

- 招标文件原文、评分标准、★条款、废标条款必须保留出处章节或页码。
- 如需要使用法律评测器的依据标签，可按以下映射处理：
  - `[用规]`：用户提供的企业内控、投标授权、内部报价规则。
  - `[要点]`：用户提示或招标文件评分/响应要点。
  - `[法规]`：法律法规、政府采购规范、交易中心规则。
  - `[惯例]`：招投标行业惯例或项目类型常见做法。
- 无法核验的依据标注“待核实”。

## 3. 脚本优先与接口契约

- 优先使用各技能 `scripts/` 中的预置脚本处理业务数据、OCR、JSON 规范化和评分；DOCX 创建、编辑和排版直接调用 `word-document-processing`。
- 保持 `/tmp` 中间产物契约不变；新增归档只能复制到 `bid_workspace/<项目名>/`，不得替代 `/tmp`。
- 所有最终交付物保存到 `/mnt/user-data/outputs/`。

## 4. 自检、换策略与熔断阈值

每个执行流程必须包含以下保护：

1. **自检**：每个关键脚本完成后检查输出文件是否存在、非空、字段/章节是否满足本技能最低要求。
2. **换策略纠错**：同一步第一次失败时，不原样重试；应切换备用路径，如 OCR、旧键名规范化或人工缺口清单。
3. **熔断阈值**：同一步连续失败 2 次后停止自动处理，向用户报告卡点、已完成产物、失败日志和建议人工动作。
4. **高风险停止**：遇到报价超限、强制资质缺失、★条款未响应、页码/签章/保证金等废标级问题时，不得提示“可直接交付”，应先输出整改清单。

## 5. 项目工作区

- 开工时可执行 `python ../_shared/bid_workspace.py --project-name "<项目名>" --status` 查看断点。
- 完成阶段后复制关键 `/tmp` 产物到工作区，并更新 `state.json`。
- 新会话恢复时先说明已完成阶段、已归档产物和建议下一步，再继续处理。
