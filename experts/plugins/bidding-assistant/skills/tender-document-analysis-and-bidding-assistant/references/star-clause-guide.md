# ★/▲/否决条款识别与响应指南

## 识别范围

解析招标文件时必须单独提取 ★、▲、否决、无效投标和实质性响应条款，并输出到 `star_clauses[]`。

识别词表：

- 显式标记：`★`、`▲`、`星号条款`、`重要条款`、`实质性要求`
- 否决表达：`无效投标`、`否决投标`、`废标`、`不予通过`、`作无效处理`
- 强制表达：`必须`、`不得`、`应当`、`须`、`不接受`、`不得偏离`、`实质性响应`
- 资格/报价/格式红线：`最高限价`、`投标有效期`、`保证金`、`签字盖章`、`联合体`、`资质条件`

## 隐性★陷阱

- 前附表中加粗、下划线、黑体或单独提示的条款，即使未标 ★，也应按强制条款候选提取。
- 评分办法中写明“不满足不得分”通常是扣分项；写明“不满足作无效投标/否决”的，按否决条款处理。
- 官方格式表、承诺书、偏离表要求“不得修改”“必须原文照抄”的，按格式类强制项处理。
- 价格、有效期、服务期、质保、付款方式等商务条款如果明确“不接受偏离”，按商务类强制项处理。

## 输出字段

`star_clauses[]` 中每条必须包含：

| 字段 | 说明 |
|---|---|
| `id` | 稳定编号，如 `S1`、`S2` |
| `type` | `★` / `▲` / `否决` / `强制` |
| `category` | 技术 / 商务 / 资格 / 报价 / 格式 / 其他 |
| `clause_text` | 条款原文，不改写 |
| `source` | 章节、页码或表格位置 |
| `response_requirement` | 投标文件应如何响应 |
| `evidence_required` | 需提供的证明材料或承诺 |

## 与废标风险联动

所有 `type` 为 `★`、`否决`、`强制` 的条款，必须同步写入 `risks[]`：

```json
{
  "risk": "★条款未响应：<条款摘要>",
  "source": "★条款",
  "level": "高",
  "avoidance": "在投标文件中逐条响应，写明完全满足，并提供对应证明材料或承诺函"
}
```

`▲` 条款不进入废标风险，但应进入评分策略和技术方案重点响应清单。

## 响应原则

- ★条款：逐条响应，一个不漏；响应文字使用“完全满足”或招标文件要求的官方措辞。
- 否决条款：必须在合规检查中置顶核验。
- ▲条款：独立小节展开，说明满足方式和超越标准的具体证据。
- 承诺类条款：招标文件提供模板时原文照抄，不得自行改写。
