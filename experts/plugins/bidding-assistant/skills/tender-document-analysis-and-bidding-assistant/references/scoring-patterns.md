# 评分模式与投标策略知识库

## 先识别评标办法

将 `scoring.evaluation_method` 归一化为以下代码，再选择解析与展示模板：

| 代码 | 识别信号 | 必提取内容 | 工作台模板 |
|---|---|---|---|
| `comprehensive_scoring` | 综合评分法、综合评估法；存在技术/商务/价格分值 | 各分项、满分、评分条件、证据、价格公式 | 交互式评分拆解器 |
| `lowest_evaluated_price` | 经评审的最低投标价法、最低评标价 | `award_rule/initial_review/detailed_review/price_adjustments` | 两阶段评审 + 资格通过清单 |
| `reasonable_low_price` | 合理低价法、基准价、有效报价区间 | `award_rule/initial_review/detailed_review/benchmark_formula` | 两阶段评审 + 基准价规则 |
| `other` / `unknown` | 其他办法或信息不足 | 原文名称、出处、待确认缺口 | 质量提示，不猜测 |

最低价不等于报价最低即当然中标；必须先通过资格、形式、响应性审查，并以招标文件载明的价格调整和排序规则为准。合理低价法也不得套用“越低越优”的结论。

## 评分三大维度

| 维度 | 典型权重 | 响应策略 |
|---|---:|---|
| 价格部分 | 30-50 分 | 识别基准价公式和异常低价红线，报价不得超过最高限价 |
| 技术部分 | 25-45 分 | 按评分表“编列内容”设置章节，每个评分点独立响应 |
| 商务部分 | 15-35 分 | 体系认证、业绩、团队、财务、信用和证书证明材料必须完整 |

## 价格评分公式

### 模式 A：均价基准法

```text
基准价 = 所有有效投标报价的平均值
价格得分 = 满分 * (1 - |报价 - 基准价| / 基准价 * Q)
```

常见规则：高于基准价扣分系数更高，低于基准价扣分系数更低。低价不能突破成本合理性。

### 模式 B：最低价基准法

```text
基准价 = 有效报价中的最低价
价格得分 = 基准价 / 投标报价 * 满分
```

适合采购标的清晰、价格竞争更强的项目。

### 模式 C：前 N 名基准法

```text
基准价 = 技术商务得分前 N 名投标人的报价均值
```

策略重点是先保证技术商务分进入有效竞争区间，再研究报价。

## 技术评分常见子项

| 子项 | 得分策略 |
|---|---|
| 技术参数响应 | ★全部满足，▲重点展开，一般条款不负偏离 |
| 系统设计方案 | 按业务、数据、应用、技术、安全、部署分层展开 |
| 项目理解 | 引用招标文件中的业务规模、现状、痛点和目标 |
| 功能需求响应 | 逐条对应需求，写明实现机制、交付物和验收证据 |
| 项目实施管理 | 进度、质量、风险、沟通、变更、验收形成闭环 |
| 售后服务方案 | 响应时间、恢复时限、服务渠道、团队和值守机制量化 |
| 培训方案 | 管理层、业务用户、运维人员分层培训 |
| 信息安全方案 | 等保、数据加密、访问控制、日志留存、应急响应 |
| 项目团队 | 人员证书、社保、类似项目经验与岗位职责匹配 |

## 商务评分常见子项

| 子项 | 得分策略 |
|---|---|
| 体系认证 | 证书页必须配官方查询截图 |
| 类似业绩 | 合同关键页、发票、发票查验截图、银行收款凭证、验收/说明文件尽量齐全 |
| 项目团队 | 人员三件套：身份证/学历、资格证书、社保证明 |
| 纳税信用 | 税务局查询截图或盖章证明，体现评价年度 |
| 质保期延长 | 不越权承诺，必须和公司实际履约能力一致 |
| 投标文件编制质量 | 导航表、目录、签章、页码、偏离表无空项 |

## `strategy` 字段填写要求

解析技能生成 `strategy` 时不得只写泛泛建议，应至少覆盖：

- `differentiation`：高权重评分项的具体突破口。
- `pricing`：价格公式类型、报价红线和需人工确认事项。
- `risks`：★/否决/高风险废标项的提交前处置动作。
- `document_focus`：商务材料、技术方案和导航表编制重点。

允许值为字符串或列表，但键名必须固定为以上四键。若上游模型产生 `key_points/strengths/weaknesses/actions` 等别名，`analysis_schema.py` 会归一化；生成阶段不得直接读取自由键名。
