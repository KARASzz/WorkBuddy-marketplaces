# 技术方案写作模式

## 总体结构

技术文件应按评分表组织，而不是按模型自由发挥：

```text
二、技术文件
├── 技术响应偏离表
├── ★条款响应对照表
├── 技术性能、参数的详细描述
└── 服务方案 / 技术方案（按评分表逐项展开）
```

每个高权重方案默认包含：

| 节 | 内容 | 得分作用 |
|---|---|---|
| x.1 招标需求响应总述 | 引用招标需求原文，再说明我方方案覆盖位置 | 让评审快速确认全覆盖 |
| x.2 项目理解与总体思路 | 业务现状、痛点、挑战、总体方法 | 体现理解深度 |
| x.3-x.7 核心方案主体 | 按评分标准“编列内容”逐块展开 | 对应评分主体 |
| x.8 人员管理及保障 | 组织架构、人员配置、职责、稳定性 | 对应团队评分 |
| x.9 评估与改进 | KPI、月报/季报、PDCA、复盘改进 | 对应服务管理 |
| x.10 服务承诺 | 信函式量化承诺，落款签章 | 可被引用打分 |

## 响应总述固定写法

每个方案第一节使用“两段式”：

1. 开头声明：我方已逐条研读招标文件相关需求，确认关键参数、服务范围、技术标准、验收要求均已在本方案中实质性响应，不存在负偏离。
2. 逐条响应：先复述招标文件原文或关键参数，再写“我方已充分理解，该要求在本方案「X节」中通过 XX 机制予以落实”。

## 文风规则

- 成段论述：每个小节按“定位/原因 -> 机制/流程 -> 量化承诺”展开，禁止一行一条的碎片清单。
- 大节引言：每个一级或二级方案节先写一段总述，再进入细项。
- 量化到数字：没有数字的承诺不得分；优先写时限、人数、频次、阈值、可用率、留存周期和验收指标。
- 呼应原文：项目规模、专有名词、技术指标、服务范围必须与招标文件一致。
- 表格边界：SLA、KPI、风险矩阵、进度计划适合表格；方案主体不得全部表格化。
- 成品语言：直接写“我方承诺”“我方方案明确”“本项目实施范围包括”，不得暴露写作过程。

## 服务承诺模板

```text
致：<招标人全称>、<代理机构全称>

我司在参与<项目名称>（招标编号：<编号>）项目投标活动中，
对本方案涉及的服务内容作出如下郑重承诺：

1. <团队规模、岗位和覆盖地域承诺>
2. <7x24 小时服务渠道承诺>
3. <SLA 响应/恢复时限承诺>
4. <制度遵从和安全合规承诺>
5. <免费服务额度或质保服务承诺>
6. <人员稳定和更换通知期承诺>
7. <知识产权和资料保密承诺>
8. <应急保障与升级路径承诺>

投标人名称：<公司名称>（盖单位公章）
日期：<日期>
```

## 篇幅基准

- 关键章节：800-1500 字。
- 高权重方案：按评分要求充分展开，不少于响应总述、项目理解、核心方案、人员保障、评估改进、服务承诺六类内容。
- 辅助章节：300-600 字，但必须有明确机制和量化信息。
