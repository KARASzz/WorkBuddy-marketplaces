# 投标文件三维审查规则

## 一、结论口径

每项检查必须同时给出：规则编号、审查规则、结论、风险等级、证据、位置、风险说明、整改动作和复验标准。

- “废标”：招标文件明确为否决、无效或强制条件，提交前必须闭环。
- “扣分”：影响评分、形式规范或证据可信度，定稿前整改。
- “提醒”：自动化无法确认或属于人工提交动作，最终复核确认。
- “通过”：仅表示当前自动检查未发现该项异常，不得表述为“完全合规”。

未在招标文件中确认否决依据时，不得仅因版式差异直接推断为废标；默认按扣分或提醒处理并标注人工核查。

## 二、编写规范性

| 编号 | 检查规则 | 主要证据 | 不通过时建议 |
|---|---|---|---|
| W01 | 招标文件明确要求提交的文件、表单和附件均已纳入投标内容 | 招标要求清单、投标内容清单 | 补齐缺失文件、表单或附件 |
| W02 | 资格、商务、技术、报价和承诺内容均有对应章节或表单 | 招标要求、内容目录、应答清单 | 为未覆盖要求补充明确应答内容 |
| W03 | 证明材料来自用户授权资料，并与应答事项唯一对应 | 材料清单、应答—证据映射 | 修正错配、漏配或来源不明材料 |
| W04 | 响应索引数据覆盖资格、符合性、评分项和强制条款 | 索引数据、要求清单 | 补齐缺失索引项和唯一章节定位键 |
| W05 | 必填业务信息具有真实值，缺失项进入待补清单 | 字段数据、缺料清单 | 补充真实信息；不得猜测或编造 |
| W06 | 项目名称、编号、主体、金额、税率、期限等跨章节一致 | 全文抽取结果、关键字段对照 | 统一冲突字段并复核来源 |
| W07 | 技术和商务偏离表一条原子要求对应一行具体响应 | 原子要求、响应行、证明材料 | 拆分合并行并补齐数值、单位、期限和条件 |
| W08 | 提交、签章、授权、保证金和密封事项已形成可执行清单 | 提交清单、招标时间节点、责任人 | 补齐责任人、截止时间和人工确认项 |

W01-W08 不直接控制字体、字号、目录、分页、表格几何、填空项、勾选项、页眉页脚或页码域。相关业务质量按 BQ01-BQ15 检查，实际修复由 `word-document-processing` 统一执行。

## 三、有效应答性

| 编号 | 检查规则 | 审查重点 |
|---|---|---|
| E01 | 资格、实质性要求及评分项逐项响应 | 要求原文、响应结论、明确承诺、量化参数、偏离 |
| E02 | 每项响应形成“要求—应答—证明—索引”证据链 | 对应原文、证明材料、证照有效期、页码定位 |
| E03 | 图片材料与应答事项一一对应 | 证照/业绩/人员/产品图片名称、章节及填充报告 |
| E04 | 商务、技术、报价和承诺口径一致 | 项目名称、编号、交期、质保、税率、总价、有效期 |
| E05 | 技术偏离表一条原子参数对应一行 | 原子要求数、独立响应行数、具体参数、数值、单位、条件、证明页 |
| E06 | 商务偏离表逐条完整应答 | 期限、起算点、金额、地点、付款/验收/质保条件及原文要素覆盖 |

规则关键词命中只能用于初筛。复杂技术和商务评分项优先使用 check_response.py --mode llm，但 LLM 结论必须保留原文证据；未找到内容统一写“未找到对应表述，建议人工核查”。

E05/E06 为提交前 P0 门禁：响应列仅写“完全响应”“完全满足”“无偏离”“按招标文件执行”，多个原子要求合并为一行，或缺少具体参数/数值/单位/期限/起算点时均不得通过。D2 无法提取关键词时必须转人工核查，不得默认通过。

## 四、风险识别

风险识别归并原 D1-D5 结果：

- D1：形式、签章、占位、目录和提交格式风险；
- D3：★条款、否决条款和废标风险是否逐项规避；
- D4：最高限价、大小写金额、税率和分项合计风险；
- D5：资格主体、证书编号、有效期和证明材料风险；
- W01-W08：必需内容遗漏、证据错配、索引缺项、字段缺失、口径冲突及提交准备风险。
- BQ01-BQ15：完整性、原文一致、图号证据、交叉引用、图表编号、占位、空标题、脱敏、表格、分页、目录、文字、承诺、日期和签章页风险。

不得只输出风险名称。每项风险须包含定位证据、整改责任人、完成时点和复验标准。

## 五、优化建议方案

- P0：废标/无效风险，提交前必须完成；
- P1：扣分、规范或证据链问题，定稿前完成；
- P2：人工复核或体验优化，最终复核时确认。

同一问题在多个维度重复出现时只保留一条主整改任务。完成后必须针对新版本重新运行对应检查，不得仅凭文字说明将状态改为通过；自动整改最多两轮，仍未关闭的事项转人工。
